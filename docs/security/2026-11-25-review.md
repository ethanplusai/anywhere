# Security review before the repository went public, 2026-11-25

A second read-only review, this time of the whole repository: the server (including local mode), the
`anywr` command, the skill's scripts, the Docker files and the workflow. Findings were confirmed
against the code, and the two High ones were reproduced, before anything was changed.

**What held up.** Account isolation on every web, API and MCP route; parameterised SQL; escaped and
sanitised rendering under a strict content security policy; sessions, password hashing and bearer
tokens; the OAuth flow; the local-mode guards (loopback only, Host and Origin checks, owner-only
token files). `pnpm audit` reports no known vulnerabilities.

## Fixed

| # | Severity | Finding | Fix | Tests |
|---|---|---|---|---|
| H1 | High | `anywr pull` wrote and deleted files at paths the server or the link file supplied, with no check that they stayed inside `.anywhere/`. A hostile server could plant `../../CLAUDE.md`; a repository that shipped its own `.anywhere/.link.json` could do the same and receive `ANYWR_TOKEN`. | Paths from the server and the link file must be page paths or they are ignored (and reported); file writes, reads and deletes refuse anything outside the folder; `ANYWR_TOKEN` is used only for a server named with `--server` or `ANYWR_SERVER`; plain `http://` is accepted only for this computer. | `packages/cli/test/trust.test.ts` |
| H2 | High | Two parsers took time that grows with the square of a page's length: the heading match behind `resume`, and the markdown renderer. One stored page could hold the single-threaded server for minutes. | The heading match is linear. The markdown parser runs under a one-second limit; a page that exceeds it is shown as its source, and remembered by content hash. | `web > renderMarkdown > gives up on a page that would hold the server...`; `web > section` |
| M1 | Medium | `docker-compose.yml` forwarded a fixed list of settings, so `ANYWHERE_SIGNUPS=closed` in `.env` never reached the server and sign-up stayed open. | The server service reads `.env` whole. | Checked with `docker compose config` |
| M2 | Medium | Client registration had a per-minute limit per address but only an hourly one server-wide, and refused requests counted, so one address could keep registration closed for everyone. | An hourly limit per address (`ANYWHERE_REGISTRATIONS_PER_ADDRESS_PER_HOUR`, 20); the shared allowance is charged only for well-formed registrations. | `security-oauth > A6 > one address cannot spend the allowance everyone shares...` |
| M4 | Medium | The local unlock token never changed and was printed at every start, so a link seen in a terminal, a screen share or a log unlocked a browser indefinitely. | The token is replaced each time it unlocks a browser. | `local > no accounts > replaces the unlock token once it has been used...` |
| L2 | Low | Local mode served the OAuth routes, so any local process could register a client and show the owner a consent page. | Those routes are not mounted in local mode. | `local > no accounts > has no app-approval routes...` |
| L3 | Low | The embedded database creates its files writable by everyone, and outside local mode its folder was readable by other users. | The folder is created, and set, owner-only. | |
| L5 | Low | The consent page looked a redirect host up on a plain object, so a host named `constructor` read as verified. Not exploitable as found. | Own-property lookup. | |
| L6 | Low | Workflow actions were pinned by tag. | Pinned by commit. | |

Two bugs that are not security: the web editor could not save a page over 64 KiB (the form limit was
smaller than the page limit), and deleting a project in local mode asked for a password that does
not exist. Both fixed, with tests.

## Open

- **Sign-up without email verification** (A7 of the first audit). In `approved` mode, whoever first
  signs up with an approved address gets the account, and sign-up says whether an address already has
  one. Needs an email provider or per-address invitation links.
- **The local session cookie is sent to every port on 127.0.0.1**, because browsers scope cookies by
  host, not port. Another web app on the same computer that the owner visits receives it. There is no
  complete fix over plain http; do not run local mode on a computer whose other local web apps you do
  not trust.
- **Sign-in lockout can be used against an account**: ten wrong passwords lock password sign-in for
  that address for fifteen minutes. Existing sessions, connected apps and tokens keep working.
- **`anywr login --token`** shows the token in the process list while it runs; paste it at the prompt
  or use `ANYWR_TOKEN` instead.
