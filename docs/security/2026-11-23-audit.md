# Security audit of the v1 server, 2026-11-23

Two independent read-only reviews of `packages/server` before any public exposure: one of identity
(sign-in, sessions, OAuth, tokens, rate limits), one of data and surfaces (isolation, injection, web
pages, export, MCP, Docker). Paths are relative to `packages/server`. Nothing was tested or changed;
every item is from reading the code unless marked suspected.

**What held up.** No tenant-isolation hole, no SQL injection, no XSS, no path traversal. PKCE, code
handling, refresh rotation with reuse detection, token hashing, CSRF and redirect validation are
correct. Versioned writes are serialised under a row lock.

**What does not.** Brute-force protection that can be bypassed or does not hold across instances; no
way to revoke access or delete data; no limits on what one account can store or load; open client
registration that can be used for phishing and abuse.

## Must fix

| # | Severity | Finding | Where | Fix |
|---|---|---|---|---|
| A1 | High | With `ANYWHERE_TRUST_PROXY=1` the first `X-Forwarded-For` entry is trusted, which the client controls behind every common proxy. Sign-in, sign-up and client registration limits are bypassed by sending a random header. Without the flag everyone behind the proxy shares one bucket, and outside `@hono/node-server` everyone is `"unknown"`. | `src/http.ts:49` | Take the right-most entry, or the Nth from the right for a configured number of trusted hops, or one named platform header. Never fall back to a shared bucket silently. |
| A2 | High | Rate limits live in process memory: no protection on serverless or with several instances, a window edge allows double, IPv6 gives 2^64 buckets, and past 10,000 keys every new key sweeps the whole map. Sign-in has no per-account limit. | `src/auth/ratelimit.ts`, `src/web/routes.ts:118,137` | Counters in Postgres (upsert on key and window). Key IPv6 by /64. Add a per-email limit with backoff on failures. Rate-limit web routes and unauthenticated 401s too. |
| A3 | High | A granted connector can never be revoked and never expires: each refresh mints a new 30-day token. No connected-apps page, no revocation endpoint, no password change, no sign-out-everywhere, no expiry option on personal access tokens. | `src/oauth/grants.ts:53-57,134-148`, `src/web/routes.ts`, `src/auth/tokens.ts` | Connected-apps page that revokes by family, RFC 7009 `/oauth/revoke`, an absolute family lifetime (for example 90 days), password change that ends all sessions and optionally all grants, optional token expiry. |
| D1 | High | A single `/mcp` request may carry a JSON-RPC batch of up to 100 calls but counts once against the limit. | `src/mcp/routes.ts:21` | Reject array bodies before the transport, or count every message. Cap concurrent requests per user. |
| D2 | High | No quotas. Every write and every append stores a full copy of the page as a revision, and revisions are never trimmed, so one account can fill the disk. | `src/service/projects.ts:161,185,265,284-296` | Per-user caps on projects, pages per project and total bytes (pages plus revisions), checked inside the write transaction. Keep the last N revisions. Do not store a full revision for each append in a short window. |
| D3 | High | `get_project` and export read every page fully into memory; the zip is built synchronously and blocks the event loop. A large project can exhaust memory and take the process down for everyone. Web routes are not rate-limited. | `src/service/projects.ts:236-262`, `src/export/zip.ts:8`, `src/web/routes.ts:203`, `src/api/routes.ts:57` | Select only the first few hundred characters for first lines. Stream the zip from a cursor with a total size cap. Rate-limit web export and page views. |
| D5 | Medium | There is no delete-project or delete-account, and deleting a page leaves every earlier version in `revisions`. | `src/service/projects.ts:300-321` | Delete project and delete account behind re-authentication (the cascades already exist). Page delete purges that page's revisions. Document backup retention. |
| A4 | Medium | Anyone can register a client named "Claude" with their own redirect, and the consent page shows that name as its heading. Private-use redirect schemes show a blank host. | `src/oauth/clients.ts:118-153`, `src/oauth/routes.ts:289-316` | Lead with "An unverified app at <redirect host>". Reserve well-known names unless the redirect host is on an allowlist. Show the full scheme. Consider a verified badge for known MCP client redirect hosts. |
| A5 | Medium | `/oauth/authorize` and `/oauth/token` fetch any https Client ID Metadata Document with no rate limit, no negative cache and no deduplication, so the server can be used as a request reflector. | `src/oauth/clients.ts:167-188`, `src/oauth/routes.ts:199,245` | Rate-limit per address and globally, negative-cache failures per host, deduplicate in-flight fetches, cap concurrency. |
| A6 | Medium | Dynamic client registration is unbounded and stores the caller's whole metadata blob. `grant_types` is echoed unvalidated. | `src/oauth/clients.ts:137-141` | Store only allowlisted fields, cap size, add a global hourly cap, delete clients with no codes or tokens after a day, validate `grant_types`. |
| D4 | Medium | Search accepts a query of any length, builds snippets from whole pages, and the pool has no statement timeout or explicit size. | `src/service/projects.ts:324-343`, `src/db/db.ts:12`, `src/mcp/server.ts:224` | Limit the query to about 256 characters, build snippets from a prefix, set `statement_timeout` and `idle_in_transaction_session_timeout`, set the pool size. |
| D6 | Medium | The web page view loads remote images, so a page written by a prompt-injected agent can send data out when the owner opens it. | `src/web/routes.ts:41`, `src/web/render.ts:81,89` | `img-src 'self' data:` and render markdown images as links. |
| D7 | Medium (design) | Page content is returned to agents with no markers and no statement that it is data, so instructions planted by one of the user's agents are read as-is by another. | `src/mcp/server.ts:43,134,136,153` | Wrap content in clear markers, say in the instructions and read-tool descriptions that page content is notes and never instructions, consider `openWorldHint: true` on read tools. |

## Should fix

| # | Severity | Finding | Where | Fix |
|---|---|---|---|---|
| A7 | Low | Sign-up reveals whether an email has an account, and with no email verification anyone can register someone else's address. | `src/auth/users.ts:28`, `src/web/routes.ts:126` | Email verification with a uniform response. |
| A8 | Low | scrypt work factor N=2^14 is below current guidance. | `src/auth/passwords.ts:3` | N=2^17 with a raised `maxmem`; rehash on login. |

| A10 | Low | OAuth tokens are not checked against the resource they were issued for, so an MCP token also works on `/api/v1`. | `src/auth/resolve.ts:24-27` | Require the expected resource per endpoint. |
| A11 | Low | Sign-in and sign-up accept a request with no `Origin` header (login CSRF). | `src/web/session.ts:42-45` | Also accept `Sec-Fetch-Site: same-origin`; reject when both are missing, or use a pre-session CSRF cookie. |
| A12 | Low | Signing in does not end the session already present; no idle timeout; expired sessions, codes and tokens are never purged. | `src/auth/sessions.ts`, `src/web/routes.ts:106-110` | Delete the incoming session on login, sliding idle timeout, periodic purge, `__Host-` cookie prefix. |
| A13 | Low | Malformed Basic credentials on the token endpoint return a 500; the registered client auth method is not enforced. | `src/oauth/clients.ts:308-309` | Return `invalid_client`; enforce the registered method. |
| A14 | Low | Any `Bearer anywr_...` guess runs an `UPDATE`, and unauthenticated traffic is unlimited. | `src/auth/resolve.ts:16-22` | Select first, update `last_used_at` at most once a minute, limit 401s per address. |
| D8 | Low | Unexpected errors in MCP tools are returned verbatim, leaking database messages. `findProject` does not validate the slug, and NUL characters are accepted in names. | `src/mcp/server.ts:37`, `src/service/projects.ts:117` | Log and return a generic error, validate the slug, reject NUL. |
| D9 | Low | Authenticated pages, exports and API responses lack `Cache-Control: private, no-store`. | `src/web/routes.ts:176-226`, `src/api/routes.ts` | Send it on every authenticated response. |
| D10 | Low | Compose falls back to a default database password, publishes the server port on all interfaces, images are not pinned, and without `DATABASE_URL` the container quietly uses the embedded database. | `docker-compose.yml:12,27,35`, `Dockerfile` | Fail on a missing password, publish on 127.0.0.1, pin digests, refuse to start in production without `DATABASE_URL`. |

## Suspected, needs a test

- DNS rebinding in the metadata-document fetch guard (`src/oauth/clients.ts:192-210`): the address is checked, then `fetch` resolves again. Pin the vetted address and stop echoing upstream status.
- The out-of-memory threshold for D3 combined with D1.
- Whether Postgres defers `ts_headline` until after the limit, and the cost of a very long OR query.
- Private-use redirect scheme parsing for unusual schemes.
- `pnpm audit --prod` has not been run.

## Accepted for now

Page content is stored as readable text (content, search text and every revision). A database or
backup leak would expose users' notes. Full-text search rules out application-level encryption
without a redesign; end-to-end encryption is on the roadmap. Rely on encrypted disks and backups,
restricted database network access and short revision retention.
