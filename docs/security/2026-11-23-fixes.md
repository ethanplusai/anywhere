# Fixes for the 2026-11-23 security audit

Every item of [2026-11-23-audit.md](2026-11-23-audit.md) is below with its status and the test that
proves it. Paths are relative to `packages/server`. Tests are named `file > describe > test`.

`pnpm --filter ./packages/cli test`. `pnpm audit --prod` at the repository root: no known
vulnerabilities. The new security tests were also run against the server as it was before the fixes,
where they fail.

Migrations added: `002_rate_limits.sql`, `003_quotas.sql`, `004_grants_sessions.sql`,
`005_oauth_clients.sql`. `001_init.sql` is untouched.

## If you embed the server as a library

- `loadConfig` throws `ConfigError` when `NODE_ENV=production` and `BASE_URL` is not https (loopback excepted), and for invalid numeric settings.
- `pgDb(url, options?)` takes optional pool options; with none it uses the defaults above (10 connections, 15 s statements). Pass `config.db` to use the environment settings.
- `purgeExpired(db)` is exported; run it on a schedule (once a day is enough).
- `AppOptions.fetch` is optional. Unset, metadata documents are fetched with pinned `node:https`. A `fetch` of your own bypasses pinning (the public-address check still runs first), so leave it unset in production.
- Behind a platform proxy, set `ANYWHERE_CLIENT_IP_HEADER` to the header it sets and clients cannot forge (`x-real-ip`, `cf-connecting-ip`, `fly-client-ip`). Without it all address-based limits share one bucket and a warning is logged once.
- The Node runtime is required (`node:https`, `node:crypto` scrypt); edge runtimes are not supported.

## Not verified

- Nothing ran against a real Postgres server: every test uses PGlite. In particular the pool's `statement_timeout` and `idle_in_transaction_session_timeout` are checked as configuration (`poolConfig`), not by a query being cancelled, and lock behaviour under real concurrency (quota charging, project-count lock) was exercised only on PGlite, which serialises connections.
- The pinned metadata fetch was tested with an injected `https.request`; no real TLS connection to a rebinding host was made.
- The image digests were current on 2026-11-23; the Docker image was not built or run.
- The web pages were checked through HTML in tests, not in a browser.
- Real MCP clients (Claude, ChatGPT, Cursor) were not run against the new consent page, the markers or the batch refusal. Claude's callback host `claude.ai` and ChatGPT's `chatgpt.com` are on the verified list from their documented callback URLs, not from a live connection.
- The per-account lockout lets someone who knows an email address lock that account out of password sign-in for 15 minutes by failing on purpose. That is the usual trade-off; existing sessions, connected apps and tokens keep working.
